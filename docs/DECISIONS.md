# Decisions

Standing decisions are in docs/factory/BATCH1_PLAN.md (Mongo instead of Postgres, Better Auth, Stripe first, Mailer interface, Vercel-first, keep 3 deployments).

## Kit v1 (5 Nov 2026)
- **D-K1 Auth = Better Auth 1.7** (magic link, passkey, TOTP, organization, api-key plugins, Mongo adapter; memory adapter in stub mode). Trayo's hand-rolled JWT/refresh/email-code code is NOT ported: Better Auth covers it with httpOnly cookies, and the kit spec + BATCH1_PLAN name Better Auth. Ported from Trayo/Jotflow instead: db interface + drivers + contract test, billing (entitlement recompute, refunds, trial-once, 2022-11-15 tolerance, app isolation), http/HttpError/readJson, ids, env flags, email adapter, consent.
- **D-K2 `__Host-` cookies:** Better Auth only auto-prefixes `__Secure-`; in production we set `useSecureCookies:false` and name each cookie `__Host-<slug>.<name>` with `secure:true, path:/`, no Domain. Dev (http) uses plain names.
- **D-K3 Next 16 Cache Components off:** classic dynamic rendering so `cookies()`/session reads need no Suspense boundaries; a product may opt in later.
- **D-K4 Billing per organization:** the Stripe customer and entitlement belong to the org (`billing_accounts`, `entitlements` keyed by org id), not the user. Multi-tier plans keyed by lookup key; `isPro` became `isPaid` + `plan`.
- **D-K5 Webhook idempotency:** `hasStripeEvent` check first, `markStripeEvent` only after successful processing (fixes the apps' "recorded before, never retried" bug). A failure returns 500 so Stripe retries.
- **D-K6 TTLs are Dates:** `stripe_events.expireAt`, `rate_limits.expireAt`, `webhook_deliveries.expireAt`, Better Auth `session/verification.expiresAt` all have TTL indexes on Date fields.
- **D-K7 Mail templates are plain HTML strings,** not react-email, to keep dependencies small; same `{subject,text,html}` shape so react-email can replace them later.
- **D-K8 Rate limiting in Mongo** (one atomic pipeline update per hit), no Redis dependency.
- **D-K9 Placeholder theme:** neutral greys + muted slate accent `#3d5a80`, Geist + Geist Mono. Products replace only the `:root` blocks and `fonts.ts`.
- **D-K10 Spacing scale enforced at compile time:** `--spacing-*: initial` in `@theme`; off-scale utilities simply produce no CSS.
- **D-K11 Stub mode:** missing `MONGODB_URI` -> memory driver; missing Stripe key -> 503 `billing_unavailable`; console mailer prints bodies only with `MAIL_CONSOLE_PRINT=1`.
- **D-K12 Atlas DB user:** the connector's create-user call needs an interactive confirmation; reported to the orchestrator, running on the memory driver until `MONGODB_URI` arrives.
- **D-P1 Postslot palette (draft, pending orchestrator approval):** the brief's Ledger Green / Archivo / Plex palette is rejected because of the palette registry (no green/teal/navy/amber families). Direction: cool neutral ramp + postmark vermilion action (#B93F17 light, #E8946B dark), danger moved to berry (#A3134A) so the accent never reads as an error. See docs/DESIGN.md.
- **D-P1 (final, supersedes the draft above) Postslot palette = postmark violet.** The draft vermilion #B93F17 was within 4 hue degrees of Straightpin tomato #B8381C, so it is replaced: action #6B3FC4 light / #B49AF0 dark, danger a true red #B3261E / #F2766E, cool neutral ramp, Geist + Geist Mono. Contrast re-computed in docs/DESIGN.md; distinctness table vs the six sibling colours in DESIGN.md section 10. The brief's Ledger Green / Archivo / Plex stays rejected.
- **D-P2 Architecture deviations from the brief:** ingest as a Next.js route handler on Vercel (not a Worker); Mongo instead of Postgres (search via compound text index, Atlas Search as the swap); token Bayes in Mongo instead of Rspamd (P1 per FR-13); delivery events normalised as `MailEvent` so a provider webhook now and KumoMTA/Haraka later share one path. Full table in docs/ARCHITECTURE.md section 0.
- **D-P3 Truth gate:** until the own MTA is live, copy says "accepted by the recipient's mail server" only; no "own mail servers" or live SPF/DKIM/DMARC claims (flag `own_mta_live`).
- **D-P4 Mock fonts:** docs/design/mock.html falls back to system faces (no network); production uses Geist as in DESIGN.md.

## M2 ingest, spam, delivery, inbox (5 Nov 2026)
- **D-M2-1 Document store on the `Db` interface:** instead of ~30 typed methods, `Db.docs<T>(name)` returns a small `DocStore` (insert returns false on duplicate `_id`, get, findOne, find, update with `$set`/`$inc`/upsert, delete, count). Filters are the Mongo subset both drivers implement (equality, `$in/$ne/$lt/$lte/$gt/$gte/$exists`, `$contains` = literal case-insensitive substring). `undefined` in an update removes the field. Natural unique keys are encoded in `_id` (`orgId|email`, `formId|email`, `scope|token`). The contract suite runs the same tests on memory and Mongo.
- **D-M2-2 Search:** `$contains` on a lowercased, capped `searchText` (regex on Mongo, escaped) instead of the planned text index. Fine for the MVP volumes; the 100k row benchmark and a text/prefix index stay in M4.
- **D-M2-3 Suppression scope:** the kit `Db.addSuppression` already takes a scope, so per-org suppression uses scope `org:<orgId>` with no interface change. Hard bounce and complaint add it; unsuppress is capped at 3 a day per org via the rate limit counter.
- **D-M2-4 Processing order:** the submission is written (`received`, plus a `received` event) before the visitor sees success. Scoring, sorting, metering and dispatch run in `after()`. The cron job `deliver-pending` re-drives submissions stuck in `received` for 2 minutes, retries queued deliveries with backoff (1 min, 5 min, 30 min, 2 h, 6 h, then `failed`), expires deferrals after 3 days and releases held submissions. Honeypot hits are stored and counted as spam synchronously. `vercel.json` runs it daily (Hobby); `infra/cron-worker` runs it every minute.
- **D-M2-5 Soft cap:** `admit()` increments the month meter and, if that goes over the plan limit, decrements it again and the submission is held (`holdReason: over_limit`), counted on the `held` meter only. `releaseHeld` runs oldest first from the cron job and from the Stripe webhook `onChange`, so a month reset or an upgrade releases them. Spam, tests and holds never count; "Mark spam" gives the unit back, "Not spam" counts it.
- **D-M2-6 Unverified recipients:** an address gets only the confirmation email. Submissions for a form with no confirmed recipient are `held` with `holdReason: recipient_unverified` (already metered once) and dispatched when the address is confirmed. The signed-in member's own address is confirmed at creation (magic link already proved it). Confirmation is a button on `/verify-recipient` (POST), so mail scanners that prefetch links cannot confirm.
- **D-M2-7 Spam scoring:** weights combine as `1 - prod(1 - w)`, quarantine at 0.7 (strict 0.5). Honeypot 1.0; time token too fast, stale or forged 0.6 (missing token adds nothing); links 0.4 + 0.15 per link over the limit; blocked phrase 0.6; script markup 0.9; disposable domain 0.5; Bayes up to 0.85. One moderate signal never quarantines alone. Bayes needs 3 spam and 3 ham trainings per scope (form, then global) before it speaks, so a cold start is rules only. Global tokens carry `orgId: "global"` and hold words only.
- **D-M2-8 Mail events:** `src/lib/mail/events.ts` defines `MailEvent` and `MailEventSource`; the Resend source verifies the Svix style signature (`MAIL_WEBHOOK_SECRET`, 5 minute tolerance) and maps `delivered` to `accepted`, `delivery_delayed` to `deferred`, `bounced` to `returned` (Permanent = hard, Transient = soft, other = block), `complained` to `complaint`. `applyMailEvent` is idempotent (`mail_inbound_events`, 7 day TTL), never moves a delivery backwards, and a soft bounce counts as deferred. The console transport plays the recipient server and accepts at once, so dev shows all stamps.
- **D-M2-9 Domain lock log:** instead of a `blockedLog` array the form keeps `blockedCount`, `lastBlockedAt`, `lastBlockedOrigin` (no array push in the DocStore). A locked form rejects posts with no Origin/Referer.
- **D-M2-10 Redirects:** a posted `redirect` is only followed when its origin is the posting origin, our own origin or in the form's allowed origins; otherwise the form's success URL, else `/thanks` on the request host. HTML errors render a small readable page (no redirect back, so no open redirect or silent drop).
- **D-M2-11 Inbox shape:** `/app` is the inbox (Inbox and Forms replace Overview in the nav; plan and usage live in a meter strip and on Billing). Filters All (everything not spam), Delivered, Spam, Held, Returned. Selection and filters are URL state, the detail is server rendered, and a client `AutoRefresh` polls every 5 s only while a delivery is open. Receipts reuse the marketing `Timeline`, `StatusChip` and `Postmark` so product and mock match.
- **D-M2-12 Not in M2 (by the roadmap):** templates beyond the default notification, the full snippet picker with the field linter and "Send test submission", owner alert emails, retention purge UI, founder admin, and the ALTCHA widget wiring in the snippets (the endpoint verifies it when a form enables it).
